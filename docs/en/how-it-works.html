How it works inside: nine stations, a gate after each

Every project passes the same stations. Each ends at a gate that code checks against the files, and it opens only when all its conditions hold.

1

Start: the project questions

Who works: Main agent + you

In«localize the game» and your answers
→
OutThe game's name, location and your permissions, saved

What it does

  • Starts the questions as soon as you ask, without “what do you mean?”
  • Suggests the folder's name as the game's name
  • Takes the game's location from you, or finds it and shows it for you to confirm
  • Saves the answers for every later session

What it never does

  • Never touches the game's files
  • Never repeats the questions in later sessions
  • Never takes “ask me” as a yes

The gate opens only when

  • The game's name is written
  • The game's folder really exists
  • The images and launch questions are answered yes or no
  • The runtime (Codex, Claude Code or both) and subscription are set
  • The subagent mode and review mode are set
2

Discovery

Who works: Main agent, with the researcher

InThe game folder (read only)
→
OutThe engine, how Arabic is drawn, and the right adapter

What it does

  • Identifies the engine and its version
  • Looks for existing Arabic tools and mods for this game
  • Decides: does the engine draw Arabic itself, or does it need pre-shaped text?

What it never does

  • Never changes a game file
  • Never bypasses protection or anti-cheat; decrypting archives or injecting code only with your per-game permission after a warning
  • Never installs a tool without recording its source and license

The gate opens only when

  • The engine is identified
  • The adapter file exists
  • The adapter declares: the engine draws Arabic itself, or it needs pre-shaping
  • Its work is on the task board, with no task left open
3

Extraction

Who works: Main agent

InThe game's files and the adapter
→
OutEvery line of the game, and the batch plan

What it does

  • Pulls every line of the game into the unit records
  • Tests the adapter with eight checks: extract and write back without breaking anything
  • Splits the work into batches and writes them in the plan

What it never does

  • Translates nothing
  • Never writes into the game folder
  • Never continues if any of the eight checks fails

The gate opens only when

  • The adapter contract passed on the current adapter and the current game text
  • Units exist and validate without errors
  • Every batch is written in the plan
  • With images in scope: text images are inventoried, or “no images” is recorded
  • Its work is on the task board, with no task left open
4

Pilot: is the Arabic right?

Who works: Main agent, then you

InMain menu, settings and the first scene
→
OutArabic showing in your game, and your confirmation recorded

What it does

  • Localizes a small batch that deliberately includes a mixed line with numbers or English names, and the longest option
  • Proofreads, builds and installs it on your copy after backing it up
  • Asks you for a short check and a screenshot of any problem
  • Fixes the rendering (font, joining, direction, clipping) and reinstalls until it is right

What it never does

  • Never localizes the rest before you confirm
  • Never fixes rendering by reversing the stored letters
  • Never records your confirmation on its own

The gate opens only when

  • The pilot batch is defined
  • Translated, proofread and installed in the game
  • Your confirmation is recorded
  • Its work is on the task board, with no task left open
5

Translation and proofreading

Who works: Translator, then a different proofreader (or the same one if you chose so)

InA batch of lines + the glossary
→
OutTranslated, proofread lines, and batches ticked ☑

What it does

  • Prepares a small brief per batch: the lines, their context and their terms
  • The translator translates the batch
  • Another agent proofreads it and records notes and a quality score
  • Localizes image text when it is in scope

What it never does

  • The translator never proofreads its own work, unless you chose “same model”
  • Never breaks code such as {name} or [key]
  • Never departs from the glossary
  • Never touches the game's files

The gate opens only when

  • Every translatable line is proofread
  • No line waits for a decision
  • No error-level problems: glossary, codes, forbidden forms
  • Every batch in the plan is ticked ☑
  • With separate review: nobody proofread their own translation
  • Every localized image: a passing record, an accepted version with its reason, and a spoiler decision
  • Its work is on the task board, with no task left open
6

Build and install

Who works: Main agent

InThe proofread lines
→
OutThe game's files in Arabic, and a backup of the originals

What it does

  • Builds the Arabic files from proofread lines only
  • Backs up every original file before replacing it
  • Always installs on your copy of the game
  • Picks a licensed Arabic font when the engine needs one

What it never does

  • Never ships an unproofread line
  • Never overwrites a file without a backup (a Claude Code hook blocks it)
  • Never installs when unsure which copy of the game is yours

The gate opens only when

  • Every line is built into a release
  • Units validate without errors
  • Its work is on the task board, with no task left open
7

Your playtest

Who works: You, then the main agent for fixes

InThe Arabic build + your reports
→
OutClosed fixes, and your acceptance recorded

What it does

  • Turns each small report into a “fix”: what happens, what should happen, and what must not change
  • Re-proofreads what was fixed and rebuilds
  • Logs bigger defects in the QA matrix

What it never does

  • Never records your acceptance on its own
  • Never closes a fix as verified without evidence, or if anything outside it changed
  • Never reopens a whole phase for a small problem

The gate opens only when

  • No open critical defects
  • No open fixes
  • Your acceptance is recorded in your words
  • Its work is on the task board, with no task left open
8

Handoff: the experiences file

Who works: Main agent, then you

InLessons recorded during the work + project facts
→
OutAn experiences-…zip file and where to send it

What it does

  • Collects the lessons the agent recorded when it found them: template bugs, limits, engine notes, tools
  • Adds what the code knows: the engine, the adapter check, fixes and results, reopened phases, the most frequent problems
  • Includes the engine profile, the adapter and reusable scripts
  • Tells you where to send it

What it never does

  • Never includes the game's text or files
  • Never leaves your paths, user name or any secret
  • Never sends the file itself

The gate opens only when

  • The experiences file was built after your acceptance and handed to you
9

Release (optional)

Who works: Main agent, only on request

InThe accepted build
→
OutA shareable localization package

What it does

  • Prepares an install and uninstall package
  • Checks licenses and what may be shared
  • Explains any install failure in one sentence: a file in use, antivirus, disk space, or a different game version

What it never does

  • Never publishes anything without your request
  • Never includes protected original game files or anything decrypted
