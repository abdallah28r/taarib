# مكتبة معرفة محركات الألعاب

تشمل نقاط البداية الحالية Unity وUnreal وGodot وRen'Py وRPG Maker وGameMaker وSource
وParadox Clausewitz/Jomini وBannerlord وDanganronpa وAge of Empires II وStardew Valley وRimWorld وMonoGame/XNA وSCUMM/ScummVM وGrimE وTelltale وDinky ومحركات PC الخاصة وAndroid APK وPS1 وPS2 (بالمحاكي). حزم PS4 خارج النطاق. ملف المحرك فرضية بداية وليس دليلا على
لعبة بعينها؛ لا ترفع معلومة إلى `verified-project` إلا بعد round-trip أو اختبار
داخل الإصدار المحدد.

يوضع هنا ملف Markdown واحد لكل محرك أو عائلة صيغ جرى العمل عليها. الهدف هو الاحتفاظ بأدوات ومعلومات وتجارب المحرك القابلة لإعادة الاستخدام، لا مجرد اقتراح روابط. هذا هو المكان الوحيد الذي تنتقل فيه المعرفة من لعبة إلى أخرى، لأن الاكتشاف يحمّل ملف المحرك.

ابدأ من `ENGINE_PROFILE_TEMPLATE.md`. افحص خريطة المسارات المعروفة أولاً،
ثم سجّل الأنماط التي تثبت للنصوص والصور والخطوط والصوت وملفات اللغة مع
الإصدار والمنصة، ولا تفترض تطابقها في كل لعبة. اجمع النتائج المؤقتة في
`work/NOTES.md`، ثم حدّث ملف المحرك مرة عند نهاية المرحلة؛ حدّثه فورًا فقط
إذا غيّر اكتشاف مثبت قرار أداة أو سلامة. افصل دائما بين «مثبت في المشروع»،
«موثق خارجيا»، و«مرشح غير مجرب».

لا تنسخ ملفات ألعاب أو مفاتيح تشفير أو بيانات محمية إلى المكتبة. الروابط والمواصفات والنتائج والأوامر والfixtures الاصطناعية مسموحة ضمن حدود المشروع.

`scripts/check_knowledge.py` يفحص وجود الأقسام وتصريح حالة الدليل فقط. نجاحه
لا يثبت صحة المعلومات أو توافق الأداة أو أن تجربة round-trip أو اختبار اللعبة
قد أُجريا؛ يراجع الآجنت هذه الأدلة في المشروع الفعلي.
