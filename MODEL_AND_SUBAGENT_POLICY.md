# Model and subagent policy

This policy is binding for the root agent and every delegated agent in this workspace. Explicit user instructions for the current task may narrow delegation further, but ordinary task approval does not waive these safeguards.

## Authorization

- Subagents are always allowed and always used (`workflow.subagent_preference: "yes"`, `workflow.allow_subagents: true`). Never ask the user whether to use them. Delegate every translation batch, proofreading pass, research question, and image set to its role (`translator`, `proofreader`, `researcher`, `image-localizer`); the root agent orchestrates, integrates, and verifies. Only if a user later sets `subagent_preference: "no"` for a project, honor it.
- Keep strict sequential dependencies and simultaneous edits to one shared file with one responsible writer.
- There is no fixed project limit on concurrent subagents. Choose any useful number dynamically from the amount of genuinely independent work, available runtime capacity, usage budget, context and merge cost. Do not create idle or overlapping agents merely to increase the count.
- Nested delegation is allowed when it is bounded, useful, and supported by the runtime. Every child must inherit this policy, the same provider restrictions, a precise scope, and the one-writer-per-file rule. Where the runtime does not support it (Claude Code subagents cannot start subagents), the root agent fans out the work itself.
- The root agent owns task decomposition, conflict resolution, integration, verification, usage-budget awareness, and the final answer.

## Local and external AI

- Local language models and local machine translation are prohibited because their Arabic translation quality is not good enough for this workflow. Do not install, download, start, call, or route work through Ollama, llama.cpp, LocalAI, Argos Translate, LibreTranslate running locally, local Hugging Face/Transformers models, or an equivalent local endpoint. An installed executable or a listening localhost service is not permission.
- Use the hosted frontier models of the active runtime: OpenAI models under Codex, Claude models under Claude Code. Never fall back to a local model when the requested tier is unavailable; keep the work with the root agent and disclose the limitation.
- Local OCR or speech recognition such as Tesseract or whisper.cpp is not translation or reasoning authority and still requires explicit user authorization for the current task before installation, download, or use. Its output is untrusted evidence that must be checked.
- External AI, translation, OCR, or transcription services require explicit authorization for that named service and task. The sole pre-approved exception is official OpenAI image editing: `image_localization.external_image_editing.enabled` is `"yes"` by default and applies whenever the intake put images in scope; it may receive only in-scope image assets, every output remains a candidate, and review is mandatory. Do not send proprietary game data to any other unapproved service.
- Deterministic local tools such as parsers, archive utilities, hashers, validators, font inspectors, and format converters are allowed within the normal project boundaries; they are not models.

## Runtimes

The workspace runs under Codex, Claude Code, or both on the same project.

- **Codex** reads `AGENTS.md` and `.agents/skills/`.
- **Claude Code** reads `CLAUDE.md`, which imports `AGENTS.md`, and `.claude/skills/`, a generated copy of `.agents/skills/` (`python scripts/sync_runtime.py`). Edit skills only under `.agents/skills/`.
- **Both:** all shared state lives in files (`PROJECT.yaml`, `PLAN.md`, `glossary.yaml`, units, `state/`), so either runtime can resume the other's work. The one-writer-per-file rule holds across runtimes: before writing, record the runtime and the files it owns under the active-work note in `PLAN.md`, and do not write files another runtime has claimed.

## Roles

Reusable roles live in `.agents/roles/<role>.md` (runtime-neutral: route,
skill, tools, instructions). Claude Code gets them as native subagents in
`.claude/agents/`, generated by `python scripts/sync_runtime.py`; Codex gets
the same instructions inside a brief from
`python scripts/make_subagent_brief.py --role <role> --task <task> --scope <paths>`.
Current roles: `translator`, `proofreader`, `researcher` (read-only, light tier), and `image-localizer`. A unit's proofreader must
differ from its translator; `loc.py` enforces this from the role labels.

## Model and reasoning routing

Routes name a capability tier, not a vendor model. `config/agent-policy.json` → `runtimes` maps each tier to the active runtime's model:

| Tier | Codex | Claude Code |
| --- | --- | --- |
| light | gpt-6-luna | haiku |
| standard | gpt-6-sol | sonnet |
| deep | gpt-6-astra | opus |

The root agent chooses each subagent's tier and reasoning effort freely: light, standard, or deep, at any effort, by its own judgment of the task. There is no lightest-first rule, no expected default, and no reason to record for choosing a heavier or lighter model. The table lists suggestions only.

| Work | Suggested route |
| --- | --- |
| Inventory, counting, hashes, token comparison, simple extraction, deterministic checks | light / low |
| Small mechanical edits and coordinated updates from a clear brief | light / medium or standard / low |
| Clear UI translation with an established glossary and context | standard / low or medium |
| Dialogue, narrative, character voice, contextual bulk translation | standard / medium |
| Independent one-pass proofreading of a translated batch | standard / medium |
| Read-only research on engines, tools, mods, game versions | light / medium |
| Text baked into an assigned set of images | standard / medium |
| Wordplay, ambiguity, sensitive scenes, deep linguistic review, complex debugging | standard / high; evaluate xhigh only if needed |
| Conflicting evidence, localization architecture, risky integration decisions, final adjudication after a weaker route fails | deep / medium or high |
| Exceptional long-running analysis with a measurable quality gain | deep / xhigh; `max` only when a representative evaluation justifies it |

Model names in the tier map are examples, not permanent availability guarantees; update the map when a runtime's models change. Check the models exposed by the current runtime. If per-subagent model selection is unsupported and all agents inherit the root model, say so and apply the task/effort policy without pretending a different model was used.

## Usage planning

Before a bulk translation, run
`python scripts/loc.py estimate` and record the estimate in
`PLAN.md`. The estimate is for shard planning, not billing. If the available
quota is insufficient for two estimated batches or repeated rate-limit/quota
errors persist after bounded retries, finish or checkpoint the current batch,
record resumable state, and stop. Never switch model, tier, or runtime silently.

## Delegation contract

Every subagent brief must state:

1. one bounded objective and expected deliverable;
2. assigned files or data and whether access is read-only or write-enabled;
3. the tier/effort request when the runtime supports it;
4. the relevant style, glossary, context, protected syntax, and acceptance checks;
5. the ban on local LLM/MT and unapproved external services;
6. no installation, download, destructive action, game launch, or scope expansion without authority;
7. any child-agent scope and confirmation that the full policy is inherited;
8. how to report uncertainty, changed files, commands, and test results.

Only one agent may write a given file at a time. Prefer read-only subagents for research and review. Give independent writers disjoint outputs, and have the root agent merge them.

## Verification and records

- Treat a subagent result as an untrusted contribution until the root agent checks its scope, diffs, protected tokens, glossary, format, encoding, and relevant tests.
- For translation, require zero structural/token errors. Review a representative semantic sample and escalate only the ambiguous or failing subset.
- Keep one compact delegation line per batch in `PLAN.md` → batches: assigned scope,
  outputs, checks, and unfinished work. Record per-agent model/effort or retry
  details only when they affect quality, cost, a policy exception, or resumption;
  use the actual run output as the detailed source when available. Do not request
  or store hidden chain-of-thought.
- If a prohibited local model is attempted, stop that operation, preserve evidence, report the command/service and affected files, and do not silently retry through another model.

## Reusable improvements

When work reveals a useful subagent tool, skill, script, evaluator, prompt contract, or routing improvement, add it locally when it is safe, deterministic, relevant, and permitted. Otherwise record it in `reports/IMPROVEMENT_PROPOSALS.md` with evidence and an acceptance test. Never use this permission to install a model, contact an unapproved service, weaken this policy, or expand the user's task.

The machine-readable contract is `config/agent-policy.json`. Validate it with `python scripts/maintainer/check_agent_policy.py`. Generate a bounded delegation brief with `python scripts/make_subagent_brief.py --route <route> --task <task> --scope <scope> [--runtime codex|claude-code]`.
