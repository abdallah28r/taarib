# Reusable improvement proposal criteria

Propose an improvement when at least one is true:

- the same manual transformation occurred more than once;
- a deterministic check would prevent a demonstrated failure;
- a format/engine fact would otherwise require rediscovery;
- a reusable script would materially reduce time or risk in another project;
- an external tool fills a verified gap better than maintaining custom code.

Do not propose generic reminders, speculative tools with no current use case, duplicated functionality, or a rule derived from one game's quirk without a clear applicability test.

Each proposal should contain:

1. Title and type: `script`, `skill`, `reference`, `tool`, `test`, or `template`.
2. Problem and evidence.
3. Proposed reusable interface and trigger.
4. What remains game-specific.
5. Dependencies, license/security/privacy considerations, and maintenance cost.
6. Minimal validation and success criteria.
7. Recommendation: `promote`, `trial`, or `keep project-only`.
